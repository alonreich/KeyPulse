# Main Window, Settings & Extracted Services

> Read `project_structure.txt` (mandatory rules + hardware guard rails) before this file. Route: [`docs/index.md`](../index.md).

## Configuration & State UI (`MainWindow.axaml` & `.cs`)
- **Dynamic Multi-Hotkey Capture**: The hotkey editor supports zero, one, or multiple keyboard combinations per action. Key combinations are managed via the `KeyCombo` box and `AddKeyButton` ("+ Add Key"), rendered as removable chips in `ComboChipsPanel`.
- **Zero-Hotkey Manual Actions**: Actions can have zero combinations, displaying `Ready (Manual)` status with purple styling. These actions can be triggered directly using the row `[Run]` button or added to the Tray Quick Action menu (`⚡`) for one-click manual firing.
- **Optional Action Display Name**: `HotkeyEntry.DisplayName` allows user-facing labeling (e.g. "Work Email Signature"), taking visual precedence in `ActionTitle` over raw action descriptors while preserving the underlying action type and target.
- **Validation & UI Responsiveness**: When text changes (`KeyCombo_TextChanged`), shortcut format validation runs synchronously and instantly, while `HotkeyManager.Probe()` availability checks are asynchronously debounced on a background task so rapid keystrokes never block or stutter the UI event loop. On conflict, `HotkeyManager.SuggestAlternative()` probes nearby combinations and offers a free one.
- **Search & Sort**: The `ListBox` binds to `VisibleHotkeys`, a filtered/sorted projection of the master `Hotkeys` collection. `RefreshVisibleHotkeys()` must be called after ANY mutation of `Hotkeys`. Matches search against `DisplayName`, `Target`, and all combinations.
- **Registration resilience**: `ApplyHotkeys()` validates only the *shape* of a target (`ValidateTargetShape`). Reachability (`IsTargetAvailableNow`) only sets a `Waiting` status; it never unregisters. A 30-second `DispatcherTimer` retries `Waiting`/`Conflict` rows so they self-heal. Reachability checks in `QueueAvailabilityCheck` are de-duplicated via `_activeAvailabilityChecks` to prevent unbounded task accumulation on `_availabilityGate`.
- **Incremental registration (CRITICAL)**: `ApplyHotkeys()` **reconciles**, it does not rebuild. For each action, it reconciles the set of `KeyCombinations` against `RegisteredHotkeyIds`, registering new combos and unregistering removed ones individually without touching unaffected combinations. Individual combination health is tracked in `ComboStatuses` and `ComboHints`, yielding `Ready`, `Partial`, `Conflict`, or `Ready (Manual)`. It must NEVER call `HotkeyManager.Clear()`: doing so released every hotkey the user owned on every add, edit, toggle, removal and 30-second retry, and any press landing in that gap was silently lost. `Clear()` is for shutdown only. A row leaving the list must have `ReleaseRegistration` called on it before removal.
- **Conflict suggestions are cached**: `SuggestAlternative` costs up to sixteen blocking register/unregister round trips. `HotkeyEntry.SuggestedForCombo` stops the retry timer recomputing it every 30 seconds forever.
- **Backup / Restore**: owned entirely by `BackupService.cs`; see [backup-restore.md](backup-restore.md).
- **Hardware consent never travels in a backup**: `BackupService.PrepareScreenBrightnessForRestore` overwrites the restored Screen Brightness `DisclaimerAccepted` with THIS PC's answer; when this PC never accepted, the feature is restored disabled and Settings shows the disclaimer right after a successful restore (`ApplyBackupPayload(..., out needsBrightnessConsent)`). Covered by `HardwareConsentAndPanelGuardTests`.
- **Theme & Dev Sandbox Window Title**: `App.ApplyTheme()` applies `AppConfig.Theme` (System / Light / Dark). `App.axaml` no longer pins `RequestedThemeVariant`. When `Program.IsDevMode` is true, `MainWindow` sets its title to `"KeyPulse [DEV SANDBOX]"` for unambiguous visual distinction, and the Settings `Check for Updates` action supports launching local installer binaries (`result.LocalInstallerPath`) when `KEYPULSE_DEV_UPDATE_SOURCE` is active (`DEVUPDATE_01`).
- **Hidden targets**: the list binds `TargetDisplay` and `TargetTooltip`, NEVER `Target`. When `IsTargetObfuscated` is set the row renders a mask under a radius-12 blur, the tool tip says "Hidden", and `MatchesSearch` skips the value. Binding `Target` there - with the secret also sitting in the tool tip - meant one second of hovering, or one search, defeated the whole feature.
- **Quick Action Configuration & Tab Navigation**: `ActionCombo` binds `SelectionChanged="ActionCombo_SelectionChanged"` (including launch, URL, folder, and text actions; Screen Brightness hotkeys are managed directly within the dedicated Screen Brightness window) and `TargetText` binds `TextChanged="TargetText_TextChanged"`. Standardized `TargetText.MinHeight = 34` prevents sudden height jumping/stutter when selecting text actions, and the editor card column 2 is constrained to star (`*`) with `TextWrapping.Wrap` enabled across all target types to prevent massive URLs/scripts from blowing out the window horizontally. Row 4 of the shortcut editor features an `Add to Quick Action Menu` checkbox (`QuickActionCheck`) beside `ObfuscateCheck`. TabIndex flows logically across all controls: `KeyCombo (0), AddKeyButton (1), ActionCombo (2), ActionNameText (3), TargetText (4), ObfuscateCheck (5), QuickActionCheck (6), ExpandTargetBtn (7), BrowseBtn (8), AddButton (9), CancelEditButton (10), SearchBox (11), Shortcut Headers (12..15), and Bottom Bar Actions (16..18)`. Shortcuts marked for quick action display a `⚡` badge next to their key combination in the list. Deleting an entry that is currently being edited calls `ClearRowEditingExcept(null)` before cancelling edit state so no stale `IsEditing` flag survives. The bottom bar provides `Screen Brightness`, `Desktop Organizer`, and `Settings` buttons.
- **Consolidated 4-Tab Categorized Settings Architecture & Modular Partial Classes (`MainWindow.axaml.cs`, `MainWindow.Settings.cs`, `MainWindow.Actions.cs`, `MainWindow.Backup.cs`)**: MainWindow is architecturally decomposed into focused partial classes: `MainWindow.Actions.cs` manages program/target resolution and executable PATH lookup (browser discovery is delegated to `BrowserDetectionService`); `MainWindow.Settings.cs` manages the settings dialog, tab lifecycles, and elevated relaunch; `MainWindow.Backup.cs` is limited to the passphrase/unlock/confirm dialogs, applying a restored payload to the live window, and monitor-aware geometry restoration (payload building, row re-creation and preference mapping live in `BackupService`). High-frequency UI operations (column resizing and column header sorting) employ `SaveConfigDebounced(400)` to eliminate UI blocking on atomic disk writes, while application shutdown and privilege elevation preserve immediate synchronous saves. The Settings modal dialog organizes all app configurations into 4 top-tier application groupings:
  1. **General**: Startup at Windows boot, tray integration, live administrator privileges state with 1-click elevation/reversion microcopy ("Run as Admin", "Revert to User"), startup admin mismatch banner with direct "Restart As Administrator" button, typing delay with inline speed validation (1–200 ms), preferred web browser selection (System Default, Chrome, Edge, Firefox, Brave) with real-time detection and fallback, and sound effects.
  2. **Appearance**: Visual color theme selection (Match Windows, Light mode, Dark mode) with WCAG AA compliant theme-aware contrast.
  3. **Displays & Icons**: Screen Brightness shortcuts/settings integration, Desktop Organizer automation (auto-restore icon positions on display change, auto-periodic snapshot backup scheduler), and display synchronization options.
  4. **Backup & Updates**: Application update checks, configurable update channels (Stable vs Beta) with conditional dropdown dimming when auto-check is disabled, configuration backup export (with optional AES-256-GCM encryption and `👁` password reveal toggle), backup restoration, and an isolated red Danger Zone factory reset.
  - **Physical Property Sheet Ear Styling & Window Lifecycle**: Tabs are rendered as top-rounded ears (`CornerRadius = 6, 6, 0, 0`) physically connected to the content page container (`pageContainer`). The active tab has zero bottom border (`BorderThickness = 1, 1, 1, 0`) and overlaps the top border of `pageContainer` by 1px with matching background (`AppPanelRaisedBrush`), creating a continuous surface identical to top-tier Windows property sheets. Inactive tabs have recessed backgrounds, subtle borders, and smooth hover/keyboard transitions. Features a single-instance guard (`_activeSettingsWindow`), modal ownership (`ShowDialogOrWindowAsync` with owner `w`), persistent window state/geometry memory (`SettingsWindowState`, `SettingsWindowX`, `SettingsWindowY`, `SettingsWindowWidth`, `SettingsWindowHeight`), a live instant search bar filtering dynamically across all settings, and contextual per-tab and global "Restore Defaults" actions with confirmation guards.
  - **Resilient Theme-Variant Brush Resolution (`AppBrush`)**: `MainWindow.AppBrush` queries `app.TryGetResource(resourceKey, app.ActualThemeVariant, out var res)` with deterministic dark/light solid brush fallbacks (and global fallback brushes in `<Application.Resources>`), guaranteeing that inactive tabs, panels, and borders never resolve to transparent brushes even when `ThemeDictionaries` lookups fail.
- **Shortcut Search Filter**: Features a left-aligned `"Search:"` label, a compact `TextBox` with constrained geometry (`MinWidth="250"`, `MaxWidth="350"`), and an embedded right-aligned `"✕"` button to immediately clear the filter.
- **Top-Tier Interactive Scroll Overflow Indicators & Navigation**: When shortcuts exceed the viewport, an interactive floating pill indicator `ScrollMoreDownPill` (`[ ▼ X more shortcuts below ▼ ]`) dynamically calculates offscreen items and smoothly pages down on click; when scrolled down, `ScrollMoreUpPill` (`[ ▲ Back to top ▲ ]`) provides immediate jump-to-top navigation. `ScrollFadeBottom` / `ScrollFadeTop` cast a theme elevation glow (`#401d4ed8` in dark mode), and the vertical scrollbar is explicitly styled (`Width="10"`, `AllowAutoHide="False"`, high-contrast thumb) so overflow is immediately obvious upon launch.
- **The shortcut table (`ShortcutHeaderGrid` + the ListBox item template)**: the header and the rows
  are two SEPARATE grids whose `ColumnDefinitions` lists must be kept identical. Column order is
  `0 Status, 1 sep, 2 Shortcut, 3 sep, 4 Action, 5 sep, 6 Target, 7 sep, 8 Actions`. Every resizable
  column binds to its own `{DynamicResource}`; the Actions column is a FIXED
  `ShortcutActionsColumnWidth` (310 = three buttons: Run, Edit, Delete + spacing) and
  must never be `Auto` - with two separate grids, `Auto` measured the word "Actions" in the header
  and the buttons in the rows, so the heading did not sit over its own column. Column 8 in both the
  header grid and the row item template is explicitly framed with `BorderThickness="0,0,1,1"` to terminate
  the table cleanly. Table headers support full WCAG AA keyboard accessibility with `Focusable="True"`,
  `TabIndex="12".."15"`, and `ShortcutHeader_KeyDown` for Tab cycling, Space/Enter sorting, and Left/Right navigation. Each splitter resizes
  the two columns it physically sits between, and `CaptureShortcutColumnWidths` reads indices
  0/2/4/6 into their matching settings.
- **Key names**: `HotkeyManager` owns the ONLY key-name table (`CanonicalKeyNames` / `KeyNameAliases`). `MainWindow.MapAvaloniaKeyToVirtualKey` is the single bridge from Avalonia's `Key` enum. Never write `Key.ToString()` into the shortcut box: `Add` (the keypad plus) used to parse as `0xBB`, the `=` key, so the shortcut the user tested was not the one that got registered.
- **No static event may outlive the window**: `_rawKeyHandler` holds the `HotkeyManager.OnRawKey` subscription so `OnClosed` can detach it. `HotkeyManager` is static, so a lambda left subscribed there keeps the window and its whole visual tree alive for the life of the process.
- **Every launched process is released**: each `Process.Start` result is wrapped in `using`. "Open folder" and "Launch program" fire on every shortcut press, so discarding the handle accumulated them between collections.
- **Non-activating notices**: `ShowActionMessage` and the typing-progress window set `ShowActivated = false` and never call `Activate()`. A shortcut failing mid-sentence must not pull the keyboard out of the app the user is typing in.
- **Elevation restarts & Wired Privilege State**: `RelaunchWithPrivilegeChange` saves BEFORE starting the elevated process and only exits if that process actually started. The old code called `Environment.Exit(0)` unconditionally, which skipped `OnClosing` and lost every unsaved edit - including when the user declined the UAC prompt. The Settings `Privileges` button dynamically reflects real wired status asynchronously (`LoadStartupStateAsync`): Green (`#2e5c46`) when effectively elevated and wired, Amber (`#8a6d1b`, "Elevate To Match Admin Mode") when claimed in Task Scheduler but running unelevated (offering a choice to restart elevated or revert Task Scheduler to user level), and Red (`#7d1d1d`) when standard user.
- **schtasks is a process**: `Program.GetAdminTaskState()` caches its answer and `Program.InvalidateAdminTaskState()` must be called after every `/Create`, `/Change` or `/Delete`. Settings loads the startup state on a background task. Never query it synchronously on the UI thread.
- **The main window opens through `MainWindow.BringToFront()` only** (ISSUE_32): a `--hidden` boot never calls `Show()`, so `Opened` fires for the FIRST time exactly when the user clicks the tray - often hours or days later. The old unconditional `if (_startHidden) Hide();` inside `MainWindow_Opened` turned that first open into a half-second flash (window appears, `Opened` hides it again); the Settings window was unaffected because it is a fresh window each time. `BringToFront()` sets `_userAskedToBeShown` BEFORE `Show()`, and only a Show nobody asked for may still be re-hidden. The show/hide/close lifecycle is logged to the debug log so window problems can finally be diagnosed from `%APPDATA%\KeyPulse\logs\keypulse_debug.txt`.

## Extracted Domain Services (TASK 10 - MainWindow de-monolithing)
MainWindow keeps every public member, XAML event handler and status string; the non-UI work behind them now lives in UI-free, test-seamed static services:
- **`StartupElevationService.cs`**: the UI-free layer over the single startup authority. `LoadSnapshot()` (off the UI thread: `InvalidateAdminTaskState`, `EnsureAdminTaskBatterySettings` when the task exists, `QueryStartupState`, `IsAdminTaskInstalled`, `IsElevated`) returns a `StartupSnapshot` with `IsUnknown` / `IsStartupOn` / `AdminTaskIneffective`. `DescribeStartup` / `DescribeStartupChange` produce the exact Settings wording plus a brush key. `SetStartup` forwards to `Program.SetStartup`. `BuildRelaunchStartInfo` / `TryStartPrivilegeRelaunch` build the UAC `runas` relaunch (`Program.ExePath`, `--setup-admin-task` / `--remove-admin-task` + `--for-user "<account>"`) and report a declined prompt instead of exiting; `ReleaseForRelaunch` stops hotkeys, invalidates the monitor cache and releases the single-instance lock before `MainWindow.RelaunchWithPrivilegeChange` calls `Environment.Exit`. The Task Scheduler XML (logon trigger, HighestAvailable run level, battery flags) is deliberately UNCHANGED in `Program.cs`. Seams: `SnapshotOverrideForTesting`, `SetStartupOverrideForTesting`, `ProcessStartOverrideForTesting`.
- **`BrowserDetectionService.cs`**: `ResolvePreference(AppConfig)` (`PreferredBrowser`, else the legacy `UseGoogleChromeForUrls` flag, else System), `IsSystemDefault`, and `TryFindBrowser` probing in fixed order HKCU App Paths -> HKLM App Paths -> HKLM WOW6432Node App Paths -> install folders (Chrome: Program Files, x86, LocalAppData; Edge: Program Files, x86; Firefox: `Mozilla Firefox` in Program Files, x86; Brave: `BraveSoftware\Brave-Browser` in Program Files, x86, LocalAppData), quotes trimmed, case-insensitive de-duplication, first existing file wins. Used by `MainWindow.LaunchUrl` and the Settings browser status line. Seams: `RegistryReadOverrideForTesting`, `FileExistsOverrideForTesting`.
- **`BackupService` enhancements**: `BuildPayload(config, hotkeys, desktopOrganizer, screenBrightness)`, `CreateHotkeyEntries(payload)` (fresh Id for blank Ids; `KeyCombinations` wins, legacy `KeyCombination` fallback), `ApplyPreferences(payload, config, normalizeTypingDelay)` (same defaults: browser from the Chrome flag, Theme System, channel Stable, settings tab clamped 0..3) and `IsSaneWindowSize`. File format, AES-256-GCM/PBKDF2 parameters and envelope are untouched.
- **`HotkeyCoordinator.cs`**: `Reconcile(entry, validCombos, callback)` is the per-row Win32 half of `ApplyHotkeys` (release removed combos individually, keep unchanged ones, register new ones, mark `Active`/`Conflict`, set `RegisteredHotkeyId`/`RegisteredCombo`) and returns `(SuccessCount, ConflictCount, FirstConflictCombo)`; `Release` / `ReleaseAll` back `MainWindow.ReleaseRegistration` / `ReleaseAllRegistrations`. It never calls `HotkeyManager.Clear()`. Seams: `RegisterOverrideForTesting`, `UnregisterOverrideForTesting`.
- Covered by `MainWindowServiceExtractionTests`.

## Directives

- **NEVER unregister a hotkey because its target is offline.** Reachability belongs to execution time, not registration time.
- **NEVER call `HotkeyManager.Clear()` to apply an edit.** Reconcile per row (see Registration resilience).
- **NEVER bind `Target` in the shortcut list, and never put it in a tool tip.** Use `TargetDisplay` / `TargetTooltip`.
- **NEVER restore a window position without checking it lands on a monitor attached to this PC.**
- **NEVER give the Actions column `Width="Auto"`, and never let the header grid and the row template drift apart.**
- **NEVER discard a `Process` returned by `Process.Start`, or the array from `GetProcessesByName`.** Wrap them in `using`.
- **NEVER subscribe an instance handler to a static event without detaching it in `OnClosed`.**
- **NEVER synchronously block the UI thread on cross-thread `HotkeyManager.Probe()` calls during keystroke input.** Validate shortcut syntax immediately and debounce availability probing to background tasks.
- **NEVER write `Avalonia.Input.Key.ToString()` into the shortcut box.** Map it to a virtual key first.
- **NEVER show a shortcut-failure notice with focus.** `ShowActivated = false`, no `Activate()`.
