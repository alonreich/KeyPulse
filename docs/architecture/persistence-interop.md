# Persistence, Crypto, IPC & COM Interop

> Read `project_structure.txt` (mandatory rules + hardware guard rails) before this file. Route: [`docs/index.md`](../index.md).

## Interop, Persistence & Utilities (`Models.cs`, `ConfigStore.cs`, `CryptoHelper.cs`, `AtomicFileWriter.cs`, `IpcService.cs`, `ComActivation.cs`)
- State is managed via the `AppConfig` class, stored at `%APPDATA%\KeyPulse\config.json`, alongside `DesktopOrganizerConfig` (`%APPDATA%\KeyPulse\desktop_organizer.json` / `.lkg.json`) and `ScreenBrightnessConfig` (`%APPDATA%\KeyPulse\screen_brightness.json` / `.lkg.json`). When `Program.IsDevMode` is true (`DEVDATA_01`), `ConfigStore.ConfigDirectory` (and `ScreenBrightnessService.AppDataFolder`) routes all configuration, Desktop Organizer layouts, and Screen Brightness presets to `KEYPULSE_DEV_DATA_DIR` / `%LOCALAPPDATA%\KeyPulse_DEV\data` (with clean-baseline snapshots persisted in `%LOCALAPPDATA%\KeyPulse_DEV\keep`), guaranteeing zero cross-contamination with `%APPDATA%\KeyPulse`. When running inside test runners (`testhost`, `vstest`), `ConfigStore.ConfigDirectory` auto-detects the test execution environment and isolates to `%TEMP%\KeyPulse_Test_Sandbox`. Pre-overwrite backups (`config.backup-<timestamp>.json`), retention pruning (newest 10), dedicated safety copies (`config.safety-shortcuts.json`), and LKG empty-overwrite protection safeguard user shortcuts against unintended wipes.
- **NativeAOT COM Interop (`ComActivation.cs`, `SetupWindow.cs`, `DesktopOrganizerService.Shell.cs`, `TaskSchedulerCom.cs`)**: NativeAOT has no built-in COM interop, so no RCWs are ever created: `ComActivation` only exposes raw `ole32!CoCreateInstance` / `CoInitializeEx`, and every COM object is driven through its vtable with `delegate* unmanaged[Stdcall]` function pointers and blittable arguments (BSTR as `IntPtr`, VARIANT as a 24-byte struct, VARIANT_BOOL as `short`). Users: `IShellLinkW` / `IPersistFile` (Start Menu shortcuts, `SetupWindow.cs`), `IShellWindows` / `IShellBrowser` / `IShellView` / `IFolderView` / `IFolderView2` (Desktop Organizer) and `ITaskService` / `ITaskFolder` / `IRegisteredTask` (admin logon task). Slot numbers come from the Windows SDK headers. **NEVER** add `[ComImport]`, `Marshal.GetObjectForIUnknown` / `GetUniqueObjectForIUnknown` or a typed `CreateInstance<T>`: they compile but fail at run time in release builds ("COM Interop requires ComWrapper instance registered for marshalling"). Enforced by `App_UsesNoBuiltInComInterop`.
- **Target protection**: `CryptoHelper` uses **DPAPI (`ProtectedData`, CurrentUser scope)** with a fixed entropy string and writes a `DPAPI:` prefix. The old `ENC:` AES format, whose key and IV were hard-coded in the executable, is still READ for migration and never written again. `TryUnprotect` returns **false** on failure and the row is flagged `TargetUnreadable`; it must NEVER return the cipher text, which is how a shortcut's target silently became the literal string `ENC:8Kd2...`. `TargetProtectionFailed` is strictly scoped to `CryptoHelper.ProtectionUnavailable && IsTargetObfuscated`, guaranteeing that ordinary non-secret targets (URLs, script paths) never trigger false DPAPI security alerts.
- **`ConfigStore` is the ONLY reader/writer of that file.** It writes atomically through `AtomicFileWriter.WriteAtomic`, and on a damaged/unreadable file it **renames the file aside** as `config.damaged-<timestamp>.json` and reports the problem. `ConfigStore.Load()` never writes `config.json` or the LKG copy (a recovery from LKG is persisted by the next ordinary save); the only disk change it can make is renaming a damaged file aside. While a save is queued, `Load()` returns the newest queued snapshot (read-your-writes).
- **Background writer**: `ConfigStore.QueueSave` serializes a snapshot on the caller's thread and returns; one thread-pool drain does the disk work. Every write carries a sequence number (`_lastWrittenSeq`) so an older snapshot never lands on a newer one; a synchronous `Save` supersedes any queued snapshot. A save whose JSON equals the file on disk is skipped. `Flush()` writes the queued snapshot on the calling thread: it runs on exit (`App.Exit_Clicked`, the main window's shutdown close, `Program.Main`'s `finally`, and `Program.ReleaseSingleInstanceLock`, which every hard `Environment.Exit` path calls) and before every rollback / wipe-safety copy. A failed background write stays queued, is logged, and raises `BackgroundSaveFailed`.
- **Single live owner**: the main window registers `ConfigStore.RegisterLiveOwner(ApplyExternalConfigMutation)`. While an owner exists, `TryUpdate` applies its mutation to the owner's in-memory `AppConfig` (on the UI thread) and the owner saves it, instead of a disk read-modify-write that the owner's next whole-object save would overwrite. Without an owner (installer/setup), `TryUpdate` keeps its read-modify-write behaviour.
- **Backup retention**: `config.backup-<utc yyyyMMdd-HHmmss>.json` is written (atomically) at most once per `BackupMinInterval` (30 min), and only when the file being replaced held shortcuts. `SelectBackupsToPrune` keeps the newest `BackupKeepRecent` (5) plus the newest backup of each of the last `BackupKeepDays` (14) days, using the timestamp in the file name; unparseable names are never deleted. Nothing in this codebase may `File.Delete` or blind-overwrite the config: doing so is how every shortcut used to vanish silently.
- **Atomic File Writing (`AtomicFileWriter`)**: Shared atomic writer utility employing `.tmp` staging, multi-attempt Win32 `File.Replace` with backup, and atomic `File.Move(overwrite: true)` fallback. Never falls back to non-atomic `File.Copy`.
- **Named Pipe IPC & Robust Byte Framing (`IpcService`)**: Low-integrity SDDL (`D:(A;;GA;;;WD)S:(ML;;NW;;;LW)`) Named Pipe server/client (`KeyPulse_IPC_Session_<SessionId>`, or `KeyPulse_IPC_DEV_Session_<SessionId>` in Dev Mode) for shell context-menu "Add to KeyPulse" requests, providing guaranteed exact 4-byte header framing (`ReadExact` / `ReadExactAsync`) and synchronous acknowledgment without file-based collision races or packet truncation. The server keeps up to 4 connections at once, each on its own pipe instance with a 5 s read deadline (`ClientReadTimeoutMs`), so one stalled client cannot block the channel. It replies only after dispatching the target; `TrySendAddTarget` returns true ONLY for a fully read, well-formed reply with `Success == true` (`IsPositiveAck`), otherwise the caller falls back to the staged file. Staged file fallback: `WriteStagedAddTarget` appends; `Program.TakeStagedAddTargets` claims the file by atomic rename to `staged-add.txt.claimed-<guid>` before reading it (a file still open by an appender fails the rename and is retried next time), and also picks up claimed files left by a crash.
- Holds an array of `HotkeyEntry` objects (DisplayName, KeyCombinations, ActionType, Target string, `IsTargetObfuscated`, `AddToQuickActionMenu`) alongside UI bounds, desktop organizer profile configurations, and screen brightness configurations.
- **Serialization Constraint**: As the app is `NativeAOT`, reflection-based JSON serialization is forbidden. `JsonSerializerContext` source generators (`AppConfigJsonContext`) are strictly enforced. All floating-point numbers support named literals (`AllowNamedFloatingPointLiterals`).

## Directives

- **NEVER overwrite live configurations with blank defaults on deserialization error.** Revert to `config.lkg.json` and lock the session to Read-Only mode (`IsReadOnlySession = true`).
- **NEVER return cipher text from a failed decrypt.** Flag `TargetUnreadable` and tell the user.
- **NEVER perform atomic disk writes or LKG updates inside `ConfigStore.Load()`.** Configuration loading must remain strictly read-only; LKG updates belong exclusively inside verified `Save()` executions.
- **NEVER assume byte-stream pipe reads return full 4-byte length headers in a single read call.** Always read length headers using exact read loops (`ReadExact` / `ReadExactAsync`).
