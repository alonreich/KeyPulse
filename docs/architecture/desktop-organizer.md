# Desktop Organizer

> Read `project_structure.txt` (mandatory rules + hardware guard rails) before this file. Route: [`docs/index.md`](../index.md).

## Desktop Organizer (`DesktopOrganizerService.cs` & `DesktopOrganizerWindow.axaml.cs`)
- **Multi-Monitor Layout Management**: Captures and restores desktop icon coordinates across single and multi-display setups. Layout profiles are persisted to `%APPDATA%\KeyPulse\desktop_organizer.json`. Each icon is saved with its monitor index and its offset from that monitor's work area; restore puts it at the same offset on the monitor with the same index (the main screen when that monitor is gone), clamped inside the work area, with no proportional scaling. When the current displays differ from the saved ones, the restore report says so (`DescribeDisplayDifference`). Features 4 customizable placement options for unsaved new icons: Center of primary screen (Default), Untouched in place, Align down right side, and Center of secondary monitor.
- **Atomic Persistence, LKG Redundancy & Empty-Overwrite Guard**: `SaveConfig` utilizes `AtomicFileWriter.WriteAtomic`, copies the existing valid `desktop_organizer.json` to `desktop_organizer.lkg.json` before overwriting, and updates `desktop_organizer.lkg.json` after each verified write. `DesktopOrganizerWindow` sets `_suppressConfigEvents = true` before `InitializeComponent()` (and omits static `SelectedIndex` in XAML) so initial control construction cannot trigger a premature save before `LoadConfig()` completes. Furthermore, `SaveConfig(config, allowEmptyProfiles)` refuses to overwrite a non-empty on-disk profile list with an empty in-memory list unless `allowEmptyProfiles: true` is explicitly passed from the user's `Delete` action.
- **Inline Profile Renaming & Non-Overlapping Profile Cards**: Each profile card uses a `WrapPanel` with clipping constraints so badges (`MANUAL (Protected)` vs. `AUTO-SNAPSHOT (x/5)`, `ACTIVE`) wrap fluidly without overflowing into column 1 or overlapping `Restore Layout` buttons. Inline renaming activates a dedicated rename editor row with explicit `[Save]` and `[Cancel]` buttons (in addition to `Enter`/`Escape` keybindings) so users never feel trapped.
- **Configurable Periodic Auto-Snapshots**: When `AutoPeriodicSnapshotEnabled` is checked, `EnsureAutoSnapshotScheduler()` runs an initial check (after a 15-minute startup delay) and a 6-hour background timer to capture automated snapshots on a customizable day interval (`AutoSnapshotIntervalDays`, `1–30 days`, default 3 days) with an interactive stepper (`− / +`). Auto-snapshots skip execution if fewer monitors are connected than previously seen or if no icon moved by more than 4 pixels compared to the newest snapshot, and automatically prune only the oldest auto-snapshot beyond `MaxAutoSnapshots = 5` while **never** auto-deleting user-created manual profiles.
- **Corrupt Profile Quarantine & Graceful Recovery**: Load failures return a typed `DesktopOrganizerLoadResult` without erasing in-memory profiles. If `desktop_organizer.json` is corrupted, it is quarantined to `desktop_organizer.damaged-<timestamp>.json` and automatic recovery from the LKG backup is attempted. If recovery fails, the UI enters Read-Only mode to protect surviving profile state from accidental overwrite.
- **Dynamic Config Path Binding (Sandbox Isolation)**: `DesktopOrganizerService.ConfigPath` and `LkgConfigPath` are expression-bodied static properties (`=> Path.Combine(ConfigStore.ConfigDirectory, ...)`), not `static readonly` fields, so every load/save/quarantine/LKG recovery re-resolves against the current `ConfigStore.ConfigDirectory`. Redirecting the directory (test sandboxes, CI, portable mode) takes effect immediately and layout data never leaks into the real `%APPDATA%` profile. Covered by `DesktopOrganizerStaticPathSandboxLeakTests.cs`.
- **Lock-Free Atomic Undo Buffer (No State Tearing)**: `_lastUndoSnapshot` is shared between the UI thread (manual restore/undo) and the display-change debounce timer thread, and is never read or assigned directly. `HasUndo` uses `Volatile.Read`; `RestoreLayoutCore` publishes pre-restore snapshots via `PublishUndoSnapshot` (`Interlocked.Exchange`, last writer wins) only when `!isUndoOperation`; `UndoLastRestore(out string report, ...)` and `UndoLastRestoreDetailedAsync` atomically claim-and-clear the snapshot via `TakeUndoSnapshot` (`Interlocked.Exchange(ref, null)`) before restoring with `UnsavedIconBehavior.LeaveInPlace`, so two concurrent undos can never apply the same snapshot. On failure/cancellation the claimed snapshot is handed back with `TryReinstateUndoSnapshot` (`Interlocked.CompareExchange(ref, snapshot, null)`), which never clobbers a newer snapshot published by a concurrent background restore. No locks are taken, so there is zero contention with `SyncLock` config I/O. Covered by `DesktopOrganizerUndoStateTearingTests.cs`.
- **Pre-Wipe Safety Preservation**: Desktop Organizer profiles are included in the setup wipe safety system via `ConfigStore.SaveAllWipeSafetyCopies()` and backup envelopes.
- **Auto-Arrange Guard**: `RestoreLayout` verifies `IsAutoArrangeActive(out bool desktopVisible)` upfront, warning the user and aborting restoration if Windows Auto-Arrange is enabled.
- **Boundary Clamping**: Anti-collision icon coordinate displacement contains horizontal boundary checks (`maxX` and `minCurX` wrap/clamp) to prevent icon displacement beyond visible monitor coordinates.
- **Shell COM Desktop Interop, Dedicated Background STA Dispatcher Queue & Non-Blocking Async Execution (Zero Memory Injection & Zero UI Freezes)**: Icon position queries and desktop layout restoration communicate natively via Windows Shell COM interfaces (`IShellWindows`, `IServiceProvider`, `IShellBrowser`, `IShellView`, `IFolderView` `cde725b0-ccc9-4519-917e-325d72fab4ce` and `IFolderView2` `1af3a467-214f-4298-908e-06b03e0b39f9`) called through raw vtable function pointers in `DesktopOrganizerService.Shell.cs` (`DesktopShellView`; slot numbers from the Windows SDK headers `ExDisp.h` / `ShObjIdl_core.h`). NativeAOT has no built-in COM interop: the former `[ComImport]` + `GetUniqueObjectForIUnknown` path failed in every release build with "COM Interop requires ComWrapper instance registered for marshalling" (Save / Restore layout only worked under the JIT). `App` logs one read-only `desktop shell reachable` line 3 s after startup (`LogDesktopShellHealthAsync`), completely eliminating cross-process memory allocation (`VirtualAllocEx`), remote process memory reading (`ReadProcessMemory`), and hooking heuristics. All Shell COM operations are decoupled and executed on a dedicated, serialized background STA worker thread (`DesktopOrganizer_STA_Worker`) via `RunInSta<T>` / `RunInStaAsync<T>` backed by `TaskCompletionSource<T>` and cooperative `CancellationToken` support. Shell COM operations NEVER execute synchronously on the Avalonia UI dispatcher thread, eliminating UI thread freezes and frame drops during slow or unresponsive Explorer COM IPC. Nested re-entrant calls on the worker thread execute directly to prevent deadlocks, and every interface pointer is released (`Marshal.Release`) by `DesktopShellView.Dispose` / `finally` blocks with `CoInitializeEx`/`CoUninitialize` apartment balancing. Asynchronous non-blocking entry points (`CaptureCurrentLayoutAsync` / `CaptureCurrentLayoutDetailedAsync`, `RestoreLayoutAsync` / `RestoreLayoutDetailedAsync`, `UndoLastRestoreDetailedAsync`, `GetDesktopIconSizeAsync`, `SetDesktopIconSizeAsync`) allow UI callers to await completions smoothly without thread stalls. Unmanaged Windows Shell COM PIDLs (`item.Pidl` in `unsavedItems`) are protected by deterministic `try ... finally` release loops executing `CoTaskMemFree` even if layout restoration is cancelled or interrupted, eliminating shell memory leaks.
- **Window layout (U7)**: top to bottom - header with the display/icon count pill; the icon-size line (`IconSizeBanner`) and the auto-arrange warning; the saved layouts (Restore / Update / Rename / Delete on each card, with an icon-size badge); the save bar (name box, **Save Current Layout**, **Undo Last Restore**, **Refresh**); a collapsed **Automatic** expander (auto-restore on display change, auto-backup interval, new-icon placement, **Reset organizer options**); the status line (empty until something happens) and **Close**. These automation options exist only here; Settings just opens this window.
- **Theme Awareness & Audio Feedback**: Resource brushes resolve dynamically against `app.ActualThemeVariant` within `ThemeDictionaries`. Interactive feedback relies strictly on embedded assembly assets (`click.wav`).

## Directives

- **NEVER execute desktop icon restoration when Windows Auto-Arrange is active.** Validate state with `IsAutoArrangeActive` first.
- **NEVER perform synchronous Win32 `SendMessage` calls to Windows Explorer from the UI thread.** Use `SendMessageTimeout` with `SMTO_ABORTIFHUNG`.
- **NEVER overwrite Desktop Organizer profile configurations directly.** Use atomic write (`.tmp` + `File.Replace`).
- **NEVER overwrite Desktop Organizer profiles with empty state upon load failure or during initial XAML construction.** Set `_suppressConfigEvents = true` before `InitializeComponent()`, retain memory state, quarantine corrupt files to `.damaged-*.json`, recover from `.lkg.json`, set read-only safeguards, and require `allowEmptyProfiles: true` only on explicit user deletion.
- **NEVER allow periodic auto-snapshots to delete manually saved Desktop Organizer profiles.** Auto-pruning (`MaxAutoSnapshots = 5`) must target exclusively profiles marked `IsAutoSnapshot == true`.
- **NEVER leak unmanaged Windows Shell COM PIDLs (`CoTaskMemFree`).** All `item.Pidl` allocations during desktop layout restoration must be protected with `try ... finally` loops ensuring immediate deallocation even on cancellation.
- **NEVER run Windows Shell COM interfaces (`IShellWindows`, `IFolderView`, `IShellView`) outside of a single-threaded apartment (STA) or without releasing every pointer.** Shell COM objects fail with `CO_E_NOTINITIALIZED` or leak OS resources on thread pool workers. Always route them through `RunInSta<T>`.
- **NEVER use `[ComImport]` interfaces or RCW helpers (`GetUniqueObjectForIUnknown`, `GetObjectForIUnknown`) in the Desktop Organizer.** They need built-in COM interop, which NativeAOT does not have. Use `DesktopShellView` (enforced by `DesktopOrganizer_UsesNoBuiltInComInterop` and `App_UsesNoBuiltInComInterop`).
- **Desktop icon size (D1-D4)**: each `DesktopLayoutProfile` stores `DesktopIconSize` / `DesktopViewMode` (`IFolderView2::GetViewModeAndIconSize`; 0 = unknown for older layouts). `RestoreLayoutCore` calls `SetViewModeAndIconSize` first when the size differs, waits `IconSizeSettleMs` (600 ms) for the desktop to re-flow, then positions icons; the report says when the size was set back and when the displays differ from the saved ones (`DescribeDisplayDifference`). The Organizer shows a live icon-size line (`IconSizeBanner`, refreshed on window activation) with **Reset to normal** when the size is not Medium (`NormalDesktopIconSize` = 48). Save / Update ask first when the size is not normal: **Reset to normal** (sets Medium, does NOT save, tells the user to arrange the icons and save afterwards), **Save at this size**, **Cancel**. Automatic snapshots are never skipped because of the icon size.
