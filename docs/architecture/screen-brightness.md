## Screen Brightness & Contrast Control (`ScreenBrightnessService.cs`, `ScreenBrightnessOverlayWindow.cs`, `ScreenBrightnessWindow.cs`, `ScreenBrightnessListReconciler.cs`, `DdcWriteSafety.cs`)
- **Movable, Resizable & Geometry-Remembering Brightness/Contrast Slider**: The tray overlay window (`ScreenBrightnessOverlayWindow`), titled **Brightness/Contrast Slider**, is fully resizable (`CanResize = true`) and movable by dragging the title bar (`BeginMoveDrag`). Its screen position and dimensions (`OverlayWindowX`, `OverlayWindowY`, `OverlayWindowWidth`, `OverlayWindowHeight`) are automatically remembered in `ScreenBrightnessConfig`. Disconnected monitors are dynamically hidden and the window scales responsively without numeric clipping or slider collisions.
- **Inter-Display Link/Sync Connectors (`⇄ SYNC`) & Clustered Pairwise Synchronization**:
  - High-contrast interactive `⇄ SYNC` toggle buttons are positioned between adjacent display cards across both the tray overlay and main Screen Brightness windows (grid columns `*, Auto, *, Auto, *`).
  - Allows granular pairwise or chained synchronization (e.g. sync Screen A ⇄ Screen B while Screen C remains independent, or link all 3 displays).
  - **Immediate In-Between Averaging on Link**: Toggling `⇄ SYNC` active immediately calculates the mathematical average of both brightness and contrast across the displays and pulls both sliders to that shared level in 0 ms.
  - **1:1 Live Lockstep Tracking**: Adjusting either Brightness or Contrast vertical slider on any display in a sync group drives companion displays in real-time 1:1 lockstep (`RequestIndividualOrLinkedChange`), updating companion sliders synchronously on UI threads with zero lag.
  - Respects each display's independent `LockRatio` configuration (e.g. if Screen A has independent contrast and Screen B has locked ratio, Brightness moves together, while Screen B's contrast mirrors its brightness).
- **Master Stepper (`−` / `+`)**: 32x30 square buttons, bold 16pt, hand cursor, pressed inset; one click steps all displays ±5%.
- **Linked "All Displays (Synced)" Master Slider with Brick Wall Clamping & Second-Pull Edge Breakthrough**:
  - Live vertical slider tracking and zero disk thrashing: moving the master slider updates display levels strictly in memory without blocking SSD disk writes, deferring persistence to the background trailing-edge flush. Vertical companion sliders track the master slider live at 60 FPS, while visual tree layout diffing (`_lastRenderedScreenConfig`) prevents tearing or layout destruction.
  - Features prominent gradient styling (`#162032` to `#1e1b4b`), vibrant border (`#38BDF8` to `#818CF8`), and `SYNCED MASTER` badge.
  - **Two-Stage Drag Boundary Physics (Brick Wall & Breakthrough)**: When dragging the master slider with differing monitor levels, the slider stops firmly at a hard brick wall once the highest screen hits 100% or lowest hits 0%, preserving relative differentials. Pushing or dragging a second time past this wall initiates a smooth breakthrough, collapsing remaining differential gaps so all displays reach 0% or 100% without stutter or 3-tick snapbacks.
  - **Virtual Differential Offset Memory in Breakthrough (`SetScreenLevelsBatch`)**: Ceiling and floor breakthrough adjustments maintain linear uncompressed virtual offsets (`VirtualBrightness`, `VirtualContrast`) in batch payloads without invoking destructive `ReanchorAllScreens()` resets on pointer release. When dragging back down from 100% (or up from 0%), each display's relative differential ratio is preserved and restored seamlessly rather than locking all displays to identical levels forever.
  - Adjusting any individual monitor slider calls `ReanchorAllScreens()`, locking in the new differential baseline for subsequent master adjustments.
  - Pointer capture drag session tracking (`_isUserDraggingMaster`) prevents background hardware state reads or transient capture events from interrupting or resetting the slider thumb mid-drag.
- **Factory Default Presets, Hotkeys & Monitor Baselines**: Out-of-the-box shipping defaults feature 50% baseline levels across Screen A, B, and C, with dedicated factory presets for Night / Low (25%), Balanced (50%), and Daylight / Competitive (75%). Dedicated Instant Screen Level hotkey shortcuts (`ScreenDirectHotkey`) default to the standard 50% baseline. Quick preset buttons at the bottom of the overlay window (`ScreenBrightnessOverlayWindow`) dynamically refresh their labels and active states in `OnServiceStateChanged` whenever presets or active levels change.
- **Custom Monitor Nicknames Everywhere**: When a user assigns a friendly nickname (e.g. *Samsung 4K*), it displays directly across slider card headers (hiding redundant slot badges), preset editor tables, direct hotkey dropdowns, and identify screen flash banners, falling back to *Screen A*, *Screen B*, *Screen C* only when no nickname is configured.
- **Dual Vertical Sliders & Lock Ratio**: Each active screen container houses two vertical sliders (`0–100`): left for **Brightness**, right for **Contrast**, with bold live numeric readouts directly above each slider, Mouse Wheel (`±2`) and Up/Down Arrow support, and a per-screen **Lock Ratio** checkbox underneath (governed globally by the default-ON **Lock Brightness & Contrast Together Tight** setting). When locked, moving either slider moves the other to the exact same value immediately; re-checking **Lock Ratio** immediately snaps Contrast to match Brightness's current value.
- **Hardware DDC/CI & NativeAOT Laptop Backlight Control**: External monitors are controlled via `dxva2.dll` (`GetNumberOfPhysicalMonitorsFromHMONITOR`, `GetPhysicalMonitorsFromHMONITOR`, `GetMonitorBrightness`, `SetMonitorBrightness`, `GetMonitorContrast`, `SetMonitorContrast`) with low-level Win32 `SetVCPFeature` (opcode `0x10` for Luminance, `0x12` for Contrast) and `GetVCPFeatureAndVCPFeatureReply` integrated as automatic fallbacks when high-level MCCS calls fail. Contrast write failures are decoupled from brightness operations so secondary contrast failures never invalidate or revert successful brightness writes. Every physical monitor handle is guaranteed to be released via `DestroyPhysicalMonitors` inside a `finally` block. Internal laptop displays are controlled via NativeAOT-safe Win32 `\\.\LCD` kernel `DeviceIoControl` (`IOCTL_VIDEO_QUERY_SUPPORTED_BRIGHTNESS`, `IOCTL_VIDEO_QUERY_DISPLAY_BRIGHTNESS`, `IOCTL_VIDEO_SET_DISPLAY_BRIGHTNESS`) used ONLY for a monitor Windows reports as a built-in panel (`ConnectedMonitorDescriptor.IsInternalPanel`, from `QueryDisplayConfig` output technology INTERNAL / DISPLAYPORT_EMBEDDED / UDI_EMBEDDED via `GetInternalPanelDeviceNames`; seam `InternalPanelDeviceNamesOverrideForTesting`). Detection failure yields no LCD writes. Hardware `Min..Max` ranges are normalized to `0–100%`: brightness 0% = hardware `Min`; contrast 0% = `Min + 5%` of range (`MinContrastFloorPercent`).
- **Sequential Multi-Display Execution & GPU I2C Multiplexer Protection (CRITICAL)**: Multi-display updates (`ApplyProfileToHardwareDeltaOnlyAsync`) are executed sequentially across connected displays in a single `foreach` loop over deterministically sorted slot indices (`bound.Keys.OrderBy(k => k)`). Parallel execution (`Parallel.ForEach`) is strictly prohibited because concurrent DDC/CI calls trigger race conditions on the GPU's display controller I2C bus multiplexer, causing bus collisions, packet drops, or driver hangs. A mandatory 30 ms settling delay (`await Task.Delay(30)`, non-blocking) is enforced between distinct physical displays, with cancellation token checks (`token.IsCancellationRequested`) at every iteration.
- **Thread-Safe DDC Monitor Session Allocation & Handle Leak Prevention (SessionLock)**: `GetOrCreateSession(hMonitor)` implements double-checked locking using a dedicated `SessionLock` with a lock-free fast-path lookup against `ActiveSessions`. This guarantees that concurrent execution across callers (`WakeDdcBus`, background throttle workers, live reads) allocates `PHYSICAL_MONITOR[]` handles via `GetPhysicalMonitorsFromHMONITOR` exactly once per monitor. Duplicate or replaced handles are deterministically disposed (`DestroyPhysicalMonitors`), eliminating unmanaged OS handle leaks in `dxva2.dll`. `DdcMonitorSession.Dispose()` enforces idempotent atomic teardown (`Interlocked.Exchange`), and `InvalidateAllSessions()` synchronizes atomically within `SessionLock` under `BusLock`.
- **Serialized Bus Arbitration & Synchronized Handle Invalidation (BusLock)**: All session creation (`GetOrCreateSession`), teardown (`InvalidateAllSessions`), wake (`WakeDdcBus`), and DDC/CI read/write routines synchronize through `BusLock` (`SemaphoreSlim(1, 1)`). Handle destruction during display topology changes or sleep wake events (`WM_DISPLAYCHANGE`, `WM_POWERBROADCAST`) is guarded under `BusLock` with bounded timeouts to eliminate Win32 `ERROR_INVALID_HANDLE` (0x6) collisions with concurrent brightness adjustments. `DdcMonitorSession` maintains an atomic `IsInvalidated` flag (`Volatile.Read` / `Interlocked.Exchange`) ensuring any held session reference halts Dxva2 calls gracefully instead of crashing the Dxva2 subsystem.
- **DDC/CI Hardware-Safety Write Policy (`DdcWriteSafety.cs`, CRITICAL)**: Monitors commonly persist brightness/contrast to NVRAM/EEPROM with limited write endurance, and scalers can lock up when the I2C bus is flooded. Every monitor write goes through the pure, unit-tested `DdcWriteSafety.WriteFeatureAsync` (sync `WriteFeature` is a test-only twin with the same policy): (1) **read first** (`ReadFeature`: high-level `GetMonitorBrightness`/`GetMonitorContrast`, then raw VCP `0x10`/`0x12` after a pause); (2) **never write without a confirmed range** (`max > min`, `current <= max`; otherwise `UnknownRange`, nothing is sent, no guessed 0..100 range); (3) **skip if the monitor already holds the target raw value** (`Unchanged`, zero NVRAM writes, covers presets re-applied and Lock-Ratio contrast); (4) otherwise at most ONE high-level set plus ONE raw `SetVCPFeature` fallback. Every DDC/CI command (read or write) is separated by `CommandSpacingMs = 50`. Only VCP `0x10` (brightness) and `0x12` (contrast) are ever written; no manufacturer codes, factory reset, power mode or `SaveCurrentMonitorSettings`. A failed write is NOT retried automatically (`ExecutePendingWriteForSlotAsync` follows up only after a successful write); `WriteSingleScreenHardwareWithRetryAsync` re-binds and retries once only when the display handle itself changed (topology change), never re-waking a monitor that refused a command. The laptop `\\.\LCD` path also queries first and skips identical levels. Under the test runner (`ConfigStore.IsTestExecutionEnvironment()`) no physical write is ever issued (`HardwareWriteOverrideForTesting` is the seam), so `dev_build.cmd` cannot touch the developer's monitors.
- **Hardware Range Clamping & Contrast Floor**: Raw values are mapped strictly inside the range the monitor reported (`DdcWriteSafety.ToRaw` / `ToPercent`). Brightness uses the full range (0% = hardware minimum). Contrast maps 0..100% onto `[min + 5% of range, max]` (`MinContrastFloorPercent = 5`) so the picture can never be driven fully black and mistaken for a dead monitor; reads apply the inverse mapping so the UI round-trips.
- **Settle-Based Write Scheduling (NVRAM Wear Limiter)**: `QueueThrottledHardwareWrite` (all slider / step-hotkey / master / batch paths) uses `DdcWriteSafety.DecideSchedule`: an isolated change after `SettleMs = 500` ms idle is written at once; a burst (held hotkey, slider drag) starts `RunSettledFlushAsync`, which writes only the newest value once input has been still for 500 ms, or at most every `MaxLatencyMs = 1500` ms during uninterrupted input (`ComputeFlushDelayMs`). Result: a held key / drag costs first + final value (+1 per 1.5 s) instead of ~8 writes per second. Shortcut-cycle presses apply immediately when isolated and only the preset the user lands on when pressed rapidly (`_lastCycleRequestUtc`). Covered by `DdcHardwareSafetyTests`.
- **Fully Asynchronous I2C Bus Arbitration (No ThreadPool Starvation)**: the per-slot write pipeline is async end to end: `ExecutePendingWriteForSlotAsync` -> `WriteSingleScreenHardwareWithRetryAsync` -> `TryWriteDdcMonitorAsync` (profile apply: `ApplyProfileToHardwareDeltaOnlyAsync`). Slot pipelines are serialised by `HardwareWriteGate` (`SemaphoreSlim`, replaces the old `lock (HardwareWriteLock)` Monitor, which cannot span an `await`). `TryWriteDdcMonitorAsync` takes exclusive bus ownership with `await BusLock.WaitAsync(BusLockTimeoutMs = 5000)` (a timed-out write is skipped and reported as failed, so the throttle cache is not updated), runs the native sequence in `WriteDdcMonitorOnBusAsync` using `DdcWriteSafety.WriteFeatureAsync` / `ReadFeatureAsync` (same read-before-write, skip-unchanged, bounded high-level + VCP retry policy as the sync versions) with `DdcPauseAsync` (`Task.Delay`) spacing, and in its `finally` awaits the `VesaInterCommandDelayMs` trailing spacing BEFORE `BusLock.Release()`, so release is deterministic on success, failure and exception and the next bus owner always gets a quiet bus. Post-write 30 ms settles are `Task.Delay`. Lock order is `HardwareWriteGate` -> `BusLock`; `WakeDdcBus` / `InvalidateAllSessions` take only `BusLock`. Test seams: `DdcBusWriteOverrideForTesting`, `TryWriteDdcMonitorForTestingAsync`, `WriteSingleScreenHardwareWithRetryForTestingAsync`, `BusLockForTesting`, `VesaInterCommandDelayMsForTesting`. Covered by `ScreenBrightnessBusLockThreadStarvationTests`.
- **Decoupled Disk Persistence (Zero Disk Thrashing on Slider Drag)**: `RequestScreenLevelChange` only updates in-memory configuration (`slotCfg.LastBrightness`, `slotCfg.LastContrast`) and avoids synchronous disk writes (`SaveConfigInternal`). Disk persistence is deferred exclusively to the background trailing-edge flush in `ExecutePendingWriteForSlotAsync` (`Task.Run(() => { lock (ConfigLock) SaveConfigInternal(cfg); })`) once slider interaction settles. In preset editor target brightness/contrast sliders, synchronous `SaveConfig` calls during drag ticks are eliminated, persisting to disk only upon `PointerReleasedEvent` and `PointerCaptureLostEvent`. Deterministic persistence on window close is guaranteed by `ScreenBrightnessService.FlushConfig()` in `Closing`/`Closed` handlers in `ScreenBrightnessWindow.cs` and `CloseSafe`/`OnOverlayClosed` in `ScreenBrightnessOverlayWindow.cs`.
- **Immutable Config Snapshots / Copy-On-Write (`LoadConfig`, `SaveConfig`, `GetLiveConfigLocked`, `CloneConfig`)**: `_cachedConfig` is PRIVATE to `ScreenBrightnessService` and never leaves it. `LoadConfig()` returns an independent deep clone (hand-written, NativeAOT-safe `CloneConfig`: new `Screens` / `Profiles` / `Targets` / `DirectHotkeys` collections and elements), so UI threads can iterate and edit freely without `InvalidOperationException: Collection was modified` or torn reads. `SaveConfig(config)` clones the incoming object BEFORE `NormalizeConfig` + disk write and publishes the clone as the new cache (the caller's object is never normalized in place). Service-internal mutators (DDC poll write-back, `RequestScreenLevelChange*`, `RequestMasterLevelChange`, `SetScreenLinkedToNext`, `SetScreenLevelsBatch`, `ReanchorAllScreens`, profile cycling/apply, `BindMonitorsToSlots` hardware-id binding) operate on the live cache via `GetLiveConfigLocked()` under `ConfigLock` and never on a caller snapshot. `NormalizeConfig` rebuilds `Screens` / `Profiles` / `Targets` into local lists and publishes each with a single reference swap (rules unchanged: default slot names, clamps to [0,100], `LockRatio` coupling, `MaxScreens` ordering). **Stale-snapshot guard**: each snapshot registers its per-screen runtime fields (`LastBrightness/Contrast`, `VirtualBrightness/Contrast`, `HardwareId`, `ModelName`) in `SnapshotBaselines`; `SaveConfig` keeps the current live value for any of those fields the caller did NOT change, so a long-lived UI snapshot can never roll back hardware state. Hotkey callbacks resolve presets / direct hotkeys by `Id` at fire time instead of capturing snapshot objects. Covered by `ScreenBrightnessMutableConfigRaceTests`.
- **Incremental Preset / Instant-Hotkey List Reconciliation (No UI Render Thrashing)**: `ScreenBrightnessWindow.OnServiceStateChanged` fires on every `StateChanged` (held step / cycle hotkeys fire it dozens of times per second), so `RenderProfilesList()` and `RenderDirectHotkeysList()` NEVER blindly `Children.Clear()`. The pure, UI-free `ScreenBrightnessListReconciler` (`ScreenBrightnessListReconciler.cs`) builds a `ProfileRowView` per preset (sorted by Screen A target then average target brightness via `SortProfiles`; cycle badge via `FormatCycleBadge`: `CYCLE STEP 1/N (LOWEST • FIRST)` / `CYCLE STEP X/N` / `NOT IN CYCLE`; active flag; delete enablement; per-connected-slot targets) and `DecideProfiles` returns `None` (step hotkeys: nothing a card shows changed), `UpdateInPlace` (same Ids, order and slot columns: `ApplyProfileRowView` updates the active highlight `AppSelectedBrush` / `AppAccentBrush`, the always-present `ACTIVE` badge's `IsVisible`, cycle badge, name, toggles, hotkey text and slider values on the existing `ProfileRowHandle` controls), `Rebuild` (preset added / deleted / reordered, slot nickname or `LockRatio` changed, monitor (un)plugged) or `DeferRebuild` (user is typing in a `TextBox` or dragging a `Slider` inside the list, tracked via a window-level tunnel `PointerPressed` handler; the rebuild runs on `LostFocus` / `PointerReleased` / `Deactivated`). In-place updates never overwrite a focused text box or a slider being dragged, and programmatic changes run under `_suppressProfileRowEvents`. The instant-hotkey list rebuilds only when `ComputeDirectHotkeysSignature` changes. Because cards now outlive many state changes, every card action (rename with 32-char / unique-name validation, Apply, Use Current Sliders, Delete, cycle / tray (max 3) toggles, hotkey record / clear, per-screen enable, target sliders) mutates the CURRENT config via `MutateProfile(id, ...)` / `PersistDirectHotkey` / `RemoveDirectHotkey` (fresh `LoadConfig()`, matched by Id) instead of saving a captured snapshot. Covered by `ScreenBrightnessUiRenderThrashingTests`.
- **Transactional Atomic Persistence & Non-Truncating LKG Backup Rotation**: Persisting screen brightness configuration (`screen_brightness.json`) routes strictly through `AtomicFileWriter.WriteAtomic` under `ConfigLock`. Staged `.tmp` files are deterministically deleted via `try...finally` scopes. To eliminate 0-byte file truncation risks during sudden power loss or crashes, `screen_brightness.lkg.json` rotates atomically before and after writes, backed by a 5-attempt retry loop with exponential backoff and structured diagnostic warnings logged via `LogDdc`.
- **Non-Blocking Serialized Live Read & User-Touch Priority**: Opening the sliders renders cached values in `0 ms` (`GetImmediateCachedStates`) and queries physical monitors sequentially on background threads with a 35 ms inter-monitor pause (`ReadAllScreensLiveAsync`), preventing GPU I2C multiplexer bus contention. Touching, dragging, or scrolling a screen's slider sets a per-screen user-touch flag (`ScreenContainerView.UserTouched = true`) that cancels/ignores the initial background read for that screen so late hardware replies never jump the slider back.
- **Async-Void Open Handlers Are Crash-Proof (`ReadAllScreensLiveOrCachedAsync`)**: `ScreenBrightnessWindow.OnWindowOpened` / `RefreshHardwareAsync` and `ScreenBrightnessOverlayWindow.OnOverlayOpened` are `async void`, so any exception escaping them reaches the dispatcher and kills the process. Both read hardware ONLY through `ScreenBrightnessService.ReadAllScreensLiveOrCachedAsync(token)`, which rethrows `OperationCanceledException` (clean abort, no status message) and turns every other non-fatal failure (`InvalidOperationException`, `Win32Exception`, torn config) into a `LiveReadOutcome` carrying `GetCachedStatesSafe()` and the error, logged via `Program.LogDebug`. On fallback the windows show `⚠️ Hardware read failed, using cached settings.` (`SetStatus(..., false)` / `_headerStatusText`) and stay populated and interactive. Both handlers additionally carry an outer non-fatal catch (`IsFatalException`: OOM / stack / AV are never swallowed) and bounds-check `_containers[st.SlotIndex]`. Slot lookups in `ReadAllScreensLiveAsyncCore` and `GetImmediateCachedStates` use `GetSlotSettingOrDefault` (index loop, default setting for an unmapped slot) instead of `First(...)`. `LiveReadOverrideForTesting` is the test seam; covered by `ScreenBrightnessAsyncVoidCrashTests`.
- **Dedicated Screen Brightness Shortcuts, Bidirectional Cycling & Granular Display Targeting**: Brightness shortcuts are managed directly in the Screen Brightness window (`ScreenBrightnessService.RegisterBrightnessHotkeys`). Global `CycleUpHotkey` and `CycleDownHotkey` step forward or backward through presets marked `IncludeInCycle` (up to 10 presets) without OSD popups or focus changes. Global `StepUpHotkey` and `StepDownHotkey` default to dual number-row and numpad bindings (`"Ctrl+Alt+=, Ctrl+Alt+NumPadAdd"` and `"Ctrl+Alt+-, Ctrl+Alt+NumPadSubtract"`), adjusting brightness across all displays in ±5% deltas (`StepDelta`). An intelligent **Multi-Monitor Differential Lock** (`LockMonitorDifferential`, default ON) preserves relative display offsets while naturally compressing at boundary limits (0% floor, 100% ceiling), falling back to cursor-focused display stepping when unlocked. Both overlay and main window feature a linked **All Displays Master Slider** with ±5% steppers. Users can configure dedicated **Instant Screen Level Hotkeys** (`ScreenDirectHotkey`, e.g. `Ctrl+Alt+1` -> Screen A to 70%) for specific monitors or all displays. Hotkey recording sets `HotkeyManager.EnableCaptureHook()` (`IsCaptureMode` flag; capture reads Avalonia `KeyDown` in the window, no OS hook), with automatic cross-action collision clearing. Each preset supports an individual direct hotkey (`Hotkey`), plus per-screen enable checkboxes (`ScreenCycleEntry.Enabled`) allowing users to target single monitors (e.g., brighten Display A only while leaving Display B untouched). Writes use the high-level MCCS call with one raw VCP `0x10`/`0x12` fallback, always after a confirmed read (see the DDC/CI Hardware-Safety Write Policy). Redundant no-op steps continue to be filtered against active connected displays.

## Directives

- **NEVER update hardware throttle cache (`LastWrittenBrightness` / `LastWrittenContrast`) on failed DDC/CI writes.** Only update throttle state when writes succeed to prevent permanent hardware write lockouts.
- **NEVER flood DDC/CI buses or spawn OSD popups during `CycleBrightness` hotkeys.** Enforce the per-screen settle-based write scheduler (500 ms settle / 1500 ms max latency) with trailing-edge final flush, read-before-write skipping of unchanged values and 50 ms command spacing, coalesce rapid shortcut presses in memory, and keep `ShowIdentifyBanners()` non-activating and click-through (`ShowActivated = false`, `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT`).
